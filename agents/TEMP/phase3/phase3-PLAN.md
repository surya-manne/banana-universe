Status: **Draft**

## TLDR

28 tasks across 7 phases: prerequisites (T0–T3, sequential), then 5 parallel streams (A–E), integration (T24–T26), and docs update (T27). Maximum parallelism: 5 concurrent engineer subagents. Zero file overlap between parallel streams. All new plugin packages are bootstrapped in prerequisites. Estimated: ~28 task units (~20 min each).

### App.ts Conflict Resolution (Streams A vs E)

Both Stream A (T7) and Stream E (T20) modify `App.ts`. To prevent conflict:

- **Stream A (T7)** modifies ONLY the `initializeControllers` method body — adds cache middleware reading inside the per-route `routers.forEach` loop, between upload and handler.
- **Stream E (T20)** modifies ONLY the top-level wiring in constructor/create — adds `this.app.use(metricsMiddleware)` before `initializeControllers` and mounts metrics/devtools endpoints after `initializeControllers` but before error middleware.
- These are non-overlapping regions of the same file. Stream A touches lines inside `initializeControllers` function. Stream E touches lines outside that function in the constructor/create flow.
- **If conflict risk is deemed too high:** Execute Stream E's T20 AFTER Stream A's T7 completes (add T7 as predecessor of T20).

### index.ts Conflict Resolution (Streams A vs E)

Both add exports to `src/index.ts`. Resolution:

- Stream A adds cache exports as a single `export *` line: `export * from './lib/Cache/Cache.decorator'` etc.
- Stream E adds metrics export: `export * from './lib/Metrics/metrics.middleware'` etc.
- These are append-only operations to different lines. Final integration task T24 verifies completeness.
- **If conflict risk is deemed too high:** Have orchestrator add ALL Phase 3 export lines to `index.ts` during T3, pointing to not-yet-existing files. Streams then only create the files.
